# Android Dependencies

## Repositories

`settings.gradle`:

```groovy
dependencyResolutionManagement {
    repositories { google(); mavenCentral() }
}
```

Keep `repositoriesMode` permissive while developing; `FAIL_ON_PROJECT_REPOS`
will reject repositories declared in module build files.

## Offline by default

The `android-build` skill runs Gradle with `--offline` and the bundled
`gradle-home/caches/modules-2`. If a dependency is missing:

```sh
OC_BUILD_ONLINE=1 bash ~/.config/opencode/skills/android-build/scripts/build.sh . debug
```

Only do this with the user's permission. The phone may be on a metered
connection.

## Diagnose a resolution failure

```sh
bash ~/.config/opencode/skills/android-build/scripts/build.sh . debug \
  :app:dependencies --configuration debugRuntimeClasspath
```

or:

```sh
# inside proot, with the same env as build.sh
"$JAVA_HOME/bin/java" -classpath "$HOME/toolchain/gradle/gradle-9.8.1/lib/gradle-gradle-cli-main-9.8.1.jar" \
  org.gradle.launcher.GradleMain --offline :app:dependencyInsight \
  --dependency androidx.core --configuration debugRuntimeClasspath
```

## Version conflicts

- Prefer explicit versions over `+` or `latest.release`.
- Use a version catalog (`gradle/libs.versions.toml`) for multi-module projects.
- Force a version only when necessary:

```groovy
configurations.all {
    resolutionStrategy.force 'androidx.core:core:1.13.1'
}
```

## Cache notes

- The bundled cache is seeded from this app's build (AGP 8.5.2, appcompat,
  material, AndroidX core). It is **not** a universal Maven mirror.
- Compose, Hilt, Room, Retrofit, Kotlin plugins and test libraries may be
  missing. Check before promising an offline build.
- Do not delete `$HOME/toolchain/gradle-home`; it contains the offline cache.
- Never commit the cache; it is generated by `scripts/make-toolchain.py`.
